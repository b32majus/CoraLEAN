# CoraLEAN — Workplan to 26 October 2026

## Objective

Have a usable CoraLEAN Alpha for the first real PROMueve Mérida working session on **26 October 2026**.

The objective is not to finish the product.

The objective is to have a sufficiently good method + Project runtime + state model + cockpit experiment to learn from real use.

## Sprint 1 — 1 to 5 October

### Method and foundation

Deliver:

- CoraLEAN Method v0.1;
- finalise core principles;
- define Guided / Partner / Expert behaviour;
- define stage/gate logic;
- define PROJECT_STATE;
- define Project instructions;
- stabilise AGENTS.md;
- define Starter Kit structure;
- continue deep research, especially Simana/Life QI and AI/QI coaching literature.

Exit criterion:

> We can initialise a CoraLEAN Project and explain exactly how Coraline should behave.

## Sprint 2 — 6 to 12 October

### CoraLEAN Alpha

Deliver:

- working ChatGPT Project configuration;
- bootstrap flow;
- first reusable Skills where available;
- initial PROJECT_STATE;
- cockpit prototype;
- initial path for importing/exporting state;
- Mérida pilot setup.

Backend decision:

- only introduce a backend if the pilot requires shared state immediately;
- do not introduce infrastructure merely to make the architecture look complete.

Exit criterion:

> Silvia can use CoraLEAN to prepare the Mérida project without manually reconstructing the method every time.

## Sprint 3 — 13 to 18 October

### Dogfooding

Silvia uses CoraLEAN as the primary partner for preparation.

Record every material friction:

- wrong question;
- missing question;
- premature solution;
- wrong phase;
- lost state;
- excessive pedagogy;
- insufficient challenge;
- poor meeting preparation;
- poor artefact generation;
- cockpit mismatch.

Exit criterion:

> We have evidence about what actually breaks or slows the workflow.

## Sprint 4 — 19 to 23 October

### Small user pilot

Include the Mérida pharmacist and, if practical, a small number of additional users.

Focus on:

- first-time onboarding;
- ability to know what to do next;
- Voice experience;
- Guided mode;
- capability transfer;
- state comprehension;
- cockpit usefulness.

Exit criterion:

> We know whether a non-expert can operate the method with decreasing support.

## 24–25 October

### Operational freeze

Freeze the version used in the 26 October workshop.

Do not introduce speculative features.

## 26 October

### First real working session

Use CoraLEAN in the real project.

Capture:

- what worked;
- what failed;
- what required Silvia;
- what the pharmacist could do independently;
- what state information was missing;
- what the cockpit needed to show.

## After 26 October

Decide whether to:

- remain Project-first;
- build/expand Desk;
- introduce a managed backend;
- introduce MCP;
- or stop at the simpler solution because it is already sufficient.

## Definition of success

Success is not feature count.

Success is:

1. better project reasoning;
2. better continuity of project state;
3. less avoidable methodological error;
4. less dependence on Silvia;
5. clear evidence about what software is actually worth building.
